# Plan File Name Trim — One-Shot Prompt

**What this is:** A workspace-agnostic instruction/prompt document. When a user points an agent at this file, the agent first **inspects the `imp-upd-plan` skill** to find redundancy in the plan filename format, then (if any is found and the user agrees) retroactively trims existing **plan filenames** in *the workspace it is currently in* to the leaner format. This is a **rename-only** job for existing files; file *contents* are never edited, and any change to the skill's own filename formula is a separate, explicitly green-lit step. Come back here when a workspace's `Archive/Plans/` may hold redundant filename parts.

---

## Why

The `session-summary` filename formula was already trimmed of redundant parts (project name, the literal word "Summary", a trailing index that echoed the `N.)` prefix). Plans may carry the same class of redundancy — e.g. a hardcoded literal word, a duplicated project/component token, or a trailing index. Unlike the summary case, this has **not** been decided yet, so the agent inspects first and proposes, rather than assuming.

---

## How The Agent Should Proceed

### Step 0 — Inspect the skill
Run the `inspect` skill against the `imp-upd-plan` skill (local master; note the global copies). Determine what, if anything, is redundant in the plan filename format, such as:

- a **project name** or **component** duplicated where the parent folder already states it,
- a **hardcoded literal word** baked into the name (you are already inside `Archive/Plans/`),
- a **trailing index/number** that merely echoes the `N.)` prefix.

Report findings. If there is **nothing redundant**, say so and stop — no task needed.

### Step 1 — Propose the target format
If redundancy exists, propose the trimmed target filename format (mirroring what was done for summaries) and get the user's decision. If the *skill itself* should be updated to codify the new format, note it — but treat skill edits + global sync as a **separate** green-lit step under the workspace's local-master-first rule. Do not edit the skill here.

### Step 2 — Make a task to fall back on
Run `imp-upd-task` and create a task capturing the retro-rename scope for this workspace's `Archive/Plans/`.

### Step 3 — Deep-dive and build the rename map
Enumerate every project subfolder and `.md` filename under `Archive/Plans/`. Compute each new name per the agreed format, keeping the `N.)` prefix and `.md` extension. Present the full **old → new rename map** for review.

### Step 4 — Execute renames (after user review)
Rename files (names only). Never edit file contents.

### Step 5 — Finalize
Only after the user gives the green light, close the task with `finalize-task`.

---

## Safety Rules

- **Inspect before acting.** Do not assume the summary-era redundancy applies verbatim to plans; derive it live from the current skill.
- **Rename only.** Never edit the contents of any plan file. Any change to the lifecycle suffix (e.g. `_plan_active` / `_plan_finalized`) must preserve the open/closed meaning — flag such structural changes for explicit user approval before executing.
- **Folder-name match required for a front trim.** Strip a leading project/component span only when it exactly matches the parent folder's project name. Otherwise leave that file's leading text alone and move on — no pausing.
- **Preserve the `N.)` prefix and `.md` extension exactly.** Do not renumber.
- **No wandering spaces.** No leading, trailing, or doubled spaces in the new name.
- **Idempotent.** Skip files already in the agreed trimmed form.
- **This workspace only.** Operate in the workspace the agent is currently in.
