# Session Summary File Name Trim — One-Shot Prompt

**What this is:** A workspace-agnostic instruction/prompt document. When a user points an agent at this file, the agent retroactively trims existing **session-summary filenames** in *the workspace it is currently in* down to the current `session-summary` skill format — removing the redundant **project-name prefix** and the redundant trailing **`Summary [N]`**. This is a **rename-only** job; file *contents* are never edited. Come back here whenever a workspace's `Archive/Summaries/` still holds legacy long-form filenames.

---

## Why

The `session-summary` skill's filename formula was shortened. Old files still carry the long form:

- Old: `N.) [Project Name] [Topic] Summary [N].md`
- New: `N.) [Topic].md`

The project name is redundant (it is already the parent folder), the word `Summary` is redundant (the files live under `Archive/Summaries/`), and the trailing `[N]` merely echoes the `N.)` prefix. This document brings legacy files in line.

---

## Target Format

```
N.) [Topic].md
```

Example: `9.) Uzzy SR Drawing Engine pt2 Summary 9.md`  →  `9.) Drawing Engine pt2.md`

---

## How The Agent Should Proceed

### Step 0 — Make a task to fall back on
Run the `imp-upd-task` skill and create a task in this workspace that captures this exact job (scope = trim summary filenames under this workspace's `Archive/Summaries/`). The task is the durable checklist the agent works against and the user finalizes later.

### Step 1 — Deep-dive the Summaries tree
Locate the Summaries root (default `Archive/Summaries/`). Enumerate every project subfolder and every `.md` filename inside each.

### Step 2 — Compute each new name (rename map, do not execute yet)
For each file, keeping the `N.)` prefix and `.md` extension:

1. **Strip the trailing `Summary [N]`** — remove a trailing ` Summary <integer>` that sits immediately before `.md`. This is always safe and applies to every file.
2. **Strip the project-name prefix** — remove the leading span *only if* it exactly matches the parent folder's name followed by a space (e.g. folder `Uzzy SR` → strip a leading `Uzzy SR `). If the leading text does **not** match the folder name, leave it alone and move on — a non-matching leading token names something other than the folder's project and is fine as-is.
3. **Normalize spaces** — collapse any double spaces and trim leading/trailing spaces so the topic reads cleanly.
4. Result: `N.) [Topic].md`.

Present the full **old → new rename map** to the user for review.

### Step 3 — Execute renames (after user review)
Rename the files (names only). Never open or edit file contents.

### Step 4 — Finalize
Only after the user gives the green light, close the task with `finalize-task`.

---

## Safety Rules

- **Rename only.** Never edit the contents of any summary file. (Known, accepted consequence: the `# H1` title inside legacy files keeps its old long form. That is intentionally out of scope here.)
- **Folder-name match required for the front trim.** Strip the leading project-name span only when it exactly matches the parent folder's project name. Otherwise leave that file's leading text alone and move on — no pausing.
- **Trailing `Summary [N]` trim is universal.** Apply it to every file, including ones whose leading token was left alone.
- **Preserve the `N.)` prefix and the `.md` extension exactly.** Do not renumber.
- **No wandering spaces.** No leading, trailing, or doubled spaces in the new name.
- **Idempotent.** If a file is already in `N.) [Topic].md` form, skip it — never double-trim.
- **This workspace only.** Operate in the workspace the agent is currently in.

## Portability Note

Copy this file into any workspace's `Documentation/` folder that needs the same cleanup. Re-number the `N.)` prefix to the next available integer in that folder. The body needs no edits — it is workspace-agnostic.
