# Skill-to-Skill Calls — Pattern and Registry

Some skills in this workspace call other skills as a mandatory step in their workflow — for
example, `imp-upd-plan` invokes `prompt-contracts`, and the three chat-migration skills invoke
`session-summary`. This is the workspace's proven, script-free pattern for one skill depending on
another. Use it whenever you build a workflow where Skill X must run Skill Y inside itself.

## The pattern (three parts)

1. **A dedicated integration section.** The calling skill's `SKILL.md` has a clearly named section
   (e.g. `## Prompt Contract Integration (Mandatory)`, `## Session Summary Integration`) that states
   the dependency is compulsory and names the exact skill to invoke.
2. **An availability guard.** Before invoking, the agent confirms the dependency skill is loaded.
   If it is not: pause, tell the user it is required, and offer to continue. If the user continues,
   fall back gracefully (reproduce the dependency's output inline from its known format) and note in
   the final report that the dedicated skill was unavailable. Never silently skip it.
3. **Pre-filled inputs.** The calling skill invokes the dependency pre-filled from context it already
   has, so the user never re-completes the dependency's input template.

This is not a script and not a literal programmatic call. It is an instruction in `SKILL.md` that the
agent honors — portable across Claude, Codex, and Antigravity, because every agent reads the same
`SKILL.md`.

## Canonical template

```text
## <Dependency> Integration (Mandatory)

Every <artifact> created or updated with this skill MUST <use the dependency> through the
`<dependency>` skill. This skill and `<dependency>` travel together; if you ever share this skill,
ship that one with it.

1. Invoke `<dependency>`, pre-filled from <context>.
2. <Do the integration-specific steps>.

**Availability guard.** Before invoking, confirm `<dependency>` is loaded.
- If NOT available, pause and tell the user it is required; ask to continue or make it available.
- If the user continues without it, reproduce the output inline and note it in the final report.
- Never silently skip it.
```

## Adoption rule

**If you adopt a skill listed as a dependant below, adopt its dependency too.** Cloning, copying, or
adapting Skill X from Uzo (U-Z-O) without Skill Y means the integration step degrades to the inline
fallback and you lose the dependency's dedicated quality. Each dependant skill's `README.md` repeats
this rule for that specific pair, and each dependency's `README.md` carries a `Depended on by` list.
