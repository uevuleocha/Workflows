# Task File Name Trim — One-Shot Prompt

**What this is:** A workspace-agnostic instruction/prompt document. When a user points an agent at this file, the agent first **inspects the `imp-upd-task` skill** to find redundancy in the task filename format, then (only if any is found and the user agrees) retroactively trims existing **task filenames** in *the workspace it is currently in*. This is a **rename-only** job for existing files; file *contents* are never edited, and any change to the skill's own filename formula is a separate, explicitly green-lit step. Come back here when a workspace's `Archive/Tasks/` may hold redundant filename parts — though the expected outcome is often "nothing to trim."

---

## Why

The `session-summary` filename formula was trimmed of redundant parts. Task filenames may or may not carry similar redundancy. In many workspaces they will already be clean — so the expected outcome of this document is often "nothing to trim." The agent verifies that by inspection rather than assuming either way.

---

## How The Agent Should Proceed

### Step 0 — Inspect the skill
Run the `inspect` skill against the `imp-upd-task` skill (local master; note the global copies). Determine whether the task filename format contains any redundancy, such as:

- a **project name** or **component** duplicated where the parent folder already states it,
- a **hardcoded literal word** baked into the name (you are already inside `Archive/Tasks/`),
- a **trailing index/number** that merely echoes the `N.)` prefix.

Report findings. **If there is nothing redundant — the likely outcome — say so and stop.** No task, no renames.

### Step 1 — Propose the target format (only if redundancy exists)
Propose the trimmed target filename format and get the user's decision. If the skill itself should change, note it as a **separate** green-lit step under the local-master-first rule. Do not edit the skill here.

### Step 2 — Make a task to fall back on
Run `imp-upd-task` and create a task capturing the retro-rename scope for this workspace's `Archive/Tasks/`.

### Step 3 — Deep-dive and build the rename map
Enumerate every project subfolder and `.md` filename under `Archive/Tasks/`. Compute each new name per the agreed format, keeping the `N.)` prefix and `.md` extension. Present the full **old → new rename map** for review.

### Step 4 — Execute renames (after user review)
Rename files (names only). Never edit file contents.

### Step 5 — Finalize
Only after the user gives the green light, close the task with `finalize-task`.

---

## Safety Rules

- **Inspect before acting.** Derive redundancy live from the current skill; do not assume the summary-era pattern applies to tasks.
- **Rename only.** Never edit the contents of any task file. Any change to the lifecycle suffix (e.g. `_pending` / `_done`) must preserve the open/closed meaning — flag such structural changes for explicit user approval before executing.
- **Folder-name match required for a front trim.** Strip a leading project/component span only when it exactly matches the parent folder's project name. Otherwise leave that file's leading text alone and move on — no pausing.
- **Preserve the `N.)` prefix and `.md` extension exactly.** Do not renumber.
- **No wandering spaces.** No leading, trailing, or doubled spaces in the new name.
- **Idempotent.** Skip files already in the agreed trimmed form.
- **This workspace only.** Operate in the workspace the agent is currently in.
