# Ecosystem cAlgo Greenlight

Explicitly authorizes direct, reviewable C# implementation work on one or more Uzzy Ecosystem bots, indicators, tools, components, or `.cs` files. It supports mandatory live-cAlgo-first editing and final workspace synchronization, phased or full-run execution, persistent `Eco-Greenlight` mode, command-line builds with automatic cBot restart and indicator reload evidence checks, the recurring Uzzy file spine, parameter-region layout, concise XML summaries, lean field documentation, intent-focused inline comments, bottom-of-file main-class/namespace boundary discipline, existing parameter-default changes through the dedicated reusable workflow, session-scoped DEBUGGING activation and mandatory reversion, exact source line reporting, selective before/after blocks, cAlgo-to-workspace synchronization, fixed read-only evidence locations, deterministic running-asset selection, and proactive baseline and post-phase log/database verification, plus a compulsory six-part change manifest and verification ledger with exact final line pointers.

## Related skills

- `green-light` - the general approval protocol this specialized skill embeds.
- `ecosystem-default-parameter-change` - performs every existing cAlgo parameter-default reset cycle needed by an approved greenlight task.
- `ltney` - blocks product-code execution while LTNEY is active unless the user grants a scoped execution override.
- `plan-this` - maintains plan-backed phased or full-run implementation work.
- `inspect` - required nested read-only review of post-build logs, databases, and output artifacts against the current implementation objective.
- `debug` - handles structured diagnosis when build or runtime defects appear.
- `push-tool` - may synchronize the live cAlgo source back to its workspace mirror.
- `finalize-plan`, `finalize-prompt`, `finalize-task`, and `finalize-report` - close their verified artifacts only when explicitly invoked.
